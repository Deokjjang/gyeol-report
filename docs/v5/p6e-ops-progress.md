# P6e-ops 진행 기록 (2026-11-04)

worktree `~/Developer/gyeol-worktrees/v5-p6e-ops`(기준선 `v5-p6e-base` = origin/v5/main c7615c9e), 브랜치 `v5/p6e-ops`. 결과·근거는 `p6e-ops-report.md`.

## 결정
- 요청 자동 처리는 DB 함수 하나(`ops_requests_autoclose`)로 두고, 환불은 DB 안(`refund_finish`·외부 환불)에서, 재생성·이용권 지급은 관리자 동작 뒤 서버가 호출 — 한 규칙·한 메모 형식.
- 보상 이용권의 "4종 한정"은 화면·판매 닫힘에 기대지 않고 이용권 자체에 상품 범위를 담아 사용 때 DB가 확인(`product_scopes`). 대운·세운 판매를 다시 열어도 보상으로는 못 만든다.
- 기존 이용권 함수는 통째로 복사하지 않고 migration 안에서 본문의 정해진 자리만 치환(`pg_temp.p6e_patch`: 자리가 정확히 기대한 횟수 나오지 않으면 중단). 원본 본문이 `report_tickets_before_launch`(launch_event가 이름을 바꿔 감싼 뒤)에 있으면 그쪽, 아니면(시험 DB) `report_tickets`에 있다.
- 환불 경고는 화면 표시에 그치지 않고 서버가 `ackWarnings` 없이는 환불 요청을 저장하지 않는다.
- 토스 상태 확인은 기존 `RefundProvider.lookup`만 사용(취소 경로는 `canPost:false`라 못 만듦). 외부 환불 기록은 서버 재조회 + PIN + 주문코드 재입력.
- 푸터 소셜 주소는 상수 한 곳, 비어 있으면 아이콘 숨김(주소를 임의로 만들지 않음). 광고 설정은 운영 `ready`를 확인한 뒤 서버 `ready`에 연결.
- 가격은 코드 변경 없이 확인·시험만(결정 대기), 바꾸는 위치와 한 가지 주의(직전 가격 허용값)를 보고에 적음.

## 진행 순서
1. migration 작성·로컬 적용 → 함수 별칭 충돌(`w`, `po`, `tier`) 수정, 시험 DB(PGlite)에서도 적용되게 원본 함수 탐지 방식으로 변경.
2. 서버(관리자 동작 5개, 보상 sync 핸들러, 환불된 책 판별), 관리자·서재·푸터 화면.
3. 시험: SQL 12(`p6eOps`), 관리자 동작 23(`adminP6e`), 푸터 5, 가격 4, 장애 강제 플래그 1 + 기존 ops 65.
4. 브라우저 E2E(로컬 dev 서버 3500, 로컬 Supabase, 토스 테스트 키 + 대역, 목업 작가): 결제→생성→요청→환불, 토스 대조·외부 환불, 보상 A·B, 선물 화면 전부. **선물 링크 거짓 성공 문구 결함 발견·수정.**
5. 동결 비교(기준 트리 3600): 8장 cmp 동일.
6. 실호출: OpenAI 임시본 1회 성공. Anthropic 키 접근이 막혀 Sonnet 정식본·교체는 미확인.
7. tsc·eslint·build, 전체 시험 비교.
