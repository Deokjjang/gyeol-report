## 장면 사실 조건 `requires` (모든 장면에 필수)
장면은 이제 `{ "text": "...", "requires": { "relationship": ..., "children": ..., "job": ... } }` 한 줄 객체다. **한 줄 형식을 유지하라.** 지금 태그는 키워드 휴리스틱이 자동으로 단 것이라 틀린 것이 섞여 있다.

| 키 | 값 | 언제 |
|---|---|---|
| relationship | `any` | 연인·배우자 유무와 무관하게 누구에게나 사실일 수 있는 장면 |
| | `single` | 지금 연인이 없다는 전제(소개팅, 썸, 혼자 보내는 기념일) |
| | `dating` | 지금 연인이 있다는 전제(애인과 데이트, 연인과 다툼) |
| | `married` | 배우자·함께 사는 가정 전제(배우자, 시댁·처가, 맞벌이, 살림을 함께 꾸림) |
| | `unmarried` | **언젠가형**: "결혼하면 / 함께 살게 되면 / 살림을 합치면" 같은 조건형. 미혼·연애 중·관계 미상 고객에게 나간다(기혼 제외) |
| children | `any` | 자녀 유무 무관 |
| | `has` | 자녀가 있다는 전제(아이 숙제를 봐 주는, 학부모 모임) |
| | `none` | **언젠가형**: "아이를 키우게 되면 / 부모가 되면" 조건형 |
| job | `any` | 직업 형태와 무관(일·과제·프로젝트·동료처럼 어디에나 있는 것) |
| | `employed` | 회사·조직 소속 전제(상사, 팀장, 출근, 결재, 부서, 월급날) |
| | `business` | 가게·사업 전제(손님, 매장, 매출, 직원을 둠, 거래처 사장) |
| | `student` | 학생 전제(수업, 교실, 담임, 학기, 학원) |

판정 원칙: **그 장면이 이 고객에게 거짓이 될 수 있으면 조건을 단다.** "회의에서 다들 고개를 끄덕일 때"는 any(회의는 어디에나 있다). "팀장이 부르면"은 employed. "애인이 서운해하면"은 dating. "좋아하는 사람이 생기면"은 any. "결혼기념일"은 married. "가족 모임"은 any. 과거 회상("학교 다닐 때")은 any.

## 지켜야 할 lint 규칙(P2 신규)
- **프로필 장면**: 영역마다 아래 세 고객 각각이 쓸 장면이 1개 이상 있어야 한다 — 미혼·직업 정보 없음 / 연애 중·직업 정보 없음 / 기혼·직업 정보 없음. 즉 영역마다 `job: any`이고 `children`이 has가 아닌 장면이 있어야 하며, relationship은 any이거나 각 상태에 맞는 것(미혼·연애 중은 single/dating/unmarried, 기혼은 married)이어야 한다.
- **결혼 영역 짝**: `marriage` 영역에는 `married` 장면 1개 이상 **과** `unmarried`(언젠가형) 장면 1개 이상이 둘 다 있어야 한다. 지금 거의 모든 항목에 언젠가형이 없다 → **항목마다 언젠가형 결혼 장면을 1~2개 새로 쓴다.** 기존 결혼 장면 중 배우자를 전제하는 것은 married로 고친다.
- **자녀 짝**: 한 영역에 `children: has` 장면이 있으면 같은 영역에 `children: none`(언젠가형) 장면도 있어야 한다.
- 영역당 장면 2~6개(MBTI signals는 3~5개). 꽉 찼으면 약한 장면 하나를 고쳐 쓴다.

## 언젠가형 장면 쓰는 법
- 조건형으로 시작하되 장면은 구체적으로: "함께 살게 되면 냉장고 칸마다 이름표를 붙이고, 공과금 날짜를 달력에 빨간 펜으로 먼저 적어 두는 쪽입니다."
- 그 항목의 이미지·성향이 보여야 한다(일반론 금지). 같은 파일 안에서 시작 구절("함께 살게 되면")을 돌려 쓰지 말고 바꿔 가며 써라: 살림을 합치면 / 한집에 살게 되면 / 결혼 이야기가 나오면 / 양가 인사를 앞두면 / 신혼집을 고르게 되면 등.
- 확정 예언 금지("결혼하게 됩니다"), 배우자 존재 단정 금지, 20~140자, 문장 ≤ 90자, MBTI 코드·명리 용어 금지(장면 문장).

## 패치 모드 (장면 검수 에이전트는 이 방식으로만 일한다 — 원본 JSON을 읽거나 고치지 말 것)
- 입력: `tools/p2-brief/b1/in/<group>.json`. 항목마다 `issues`(지금 규칙 위반)와 `scenes[영역] = [[번호, 문장, "relationship/children/job"], ...]`. `partial: true`인 영역은 의심 장면만 보여 준 것이다(나머지는 any/any/any로 안전). 결혼·연애 영역과 위반이 있는 영역은 전부 보여 준다. 항목 성격은 `easyName`·`oneLiner`·`metaphor`로 파악한다.
- 출력: `tools/p2-brief/b1/out/<group>.json` 하나만 쓴다.
  `{ "retag": [[id, 영역, 번호, "rel/children/job"]], "replace": [[id, 영역, 번호, "새 문장", "rel/children/job"]], "add": [[id, 영역, "새 문장", "rel/children/job"]] }`
  - 태그만 틀리면 retag, 문장을 고쳐 써야 하면 replace(같은 번호), 새 장면은 add. 번호는 입력에 적힌 원래 번호.
  - 영역당 장면 수 상한(명리 6, MBTI 5)을 넘기면 add 대신 약한 장면을 replace.
- 검사: `node tools/p2-brief/b1/b1.mjs check <group>` → `errors: 0`이 될 때까지 패치를 고친다. 이 검사는 패치를 메모리에서만 적용해 장면 규칙·문장 규칙·DB 전체 중복을 본다(파일은 바뀌지 않는다). 실제 반영은 메인이 한다.
- 중복 모티프: 새 문장을 쓰기 전 `grep -rn '<핵심 구절>' src/data/knowledge-v5/ | head -3`으로 같은 그림이 있는지 본다.
