## 결정

1. **이미지 변형 필드**: 지식 요소에 `imageVariants: Image[]`(선택)를 더한다. 감지 빈도 상위 30%(`src/lib/brief/data/feature-frequency.json` 252개 중 76개)는 lint가 3개 이상을 강제한다. 변형은 기본 이미지의 핵심 대상(약방·촛불 등)을 유지하고 틀·장면만 바꾼다. 브리프는 [기본 + 변형] 중 시드로 하나를 고른다(같은 요소라도 고객마다 다른 그림).
2. **장면 보강 범위**: 같은 76개 요소의 7영역 장면을 영역당 3개 이상으로(부족분 377개). 새 장면은 기본 `any/any/any`(직업 정보 없음 고객도 쓸 수 있게) — 직업 맞춤은 작가가 소품 사전으로 한다.
3. **소품 사전 위치**: 해석 지식이 아니라 고객 사실 → 생활 소품 매핑이라 `src/lib/brief/data/props.json`(직업군 58개, 직업 상태 10, 관계 4, 나이대 6)에 둔다. 매칭은 위에서부터 첫 일치. 장마다 `sceneHint` 2개(일·돈·배움=직업, 사랑·결혼=관계, 사람·혼자=나이대 소품을 줄별 커서로 돌림). 궁합은 두 사람이라 넣지 않는다.
4. **결혼·자녀 언젠가형 장면**: unmarried·children none 태그 또는 "결혼하면·함께 살게·아이를 키우" 문구가 있는 장면은 연애 상품 전체와 종합 '사람 사이에서' 장에서만 고른다. Fusion 장면은 연애 상품에서만 붙인다.
5. **A4 "앞에서 본 X" 판정**: X 앞 24자 안에 특성의 쉬운 이름·이름·이미지 끝 낱말이 있으면 그 특성으로 보고, 책 앞쪽 글에 그 낱말이 하나도 없으면 "앞에서 본"을 지우고 "쉬운 이름(이름)은 이미지 같은 기운입니다." 한 문장을 앞에 둔다. 특성을 못 찾으면 "앞에서 본"만 지운다.
6. **A6 금지 패턴은 자기 지칭·권유 꼴만**: 지식 DB에 "숫자와 근거가 없으면 도장을 찍지 않습니다", "관계를 끊습니다" 같은 행동 묘사가 있어, "궁합·풀이·해석… 근거가 없다/재미로", "헤어지는 게 낫다/관계를 끊는 게" 같은 꼴만 지운다(지식 DB 전수 오탐 0).
7. **궁합 점수는 하위 점수를 보여 주지 않는다**: v5 Book 점수 쪽은 구성요소를 3칸 수준(좋음 3·보통 2·조율 1)으로만 보여 준다. 하위 점수 평균이 총점과 달라 보이는 모순을 막기 위함(단조 변환이라 총점 순서는 원점수 순서와 같다).
8. **A7 보충 순서**: 그 장 특성의 세기·둘째 장점 → 안 쓴 Fusion → 과사용(따뜻한 마무리 문장 붙임) → MBTI 기능 → 안 쓴 원국/궁합 절 → 다른 특성. 책 안 같은 문장은 넣지 않는다. 남은 1장(궁합 부모·자녀 결정론 책 5장, 877자)은 책 전체가 결정론일 때 재료가 앞 장에서 다 쓰인 경우라 그대로 둔다.
9. **문체 예시**: 壬午·ESTP·도화·역마(종합 2장), 甲申·INTJ·홍염·편관(연애 4장). 시험 고객 4명과 일주·MBTI·주요 신살이 겹치지 않고, 지식 DB와 15자 창 겹침 0(옛 예시는 5곳 겹쳤다).
10. **결제 경로 v5(B)**: SQL(claim·lease 10분·finish_job)과 결제·환불 상태 전이는 그대로 두고 `runPaidReportJob`에 선택 훅(`PaidV5Builder`)만 더했다. 훅은 결제 워커 배선(`paidRuntime`)이 `WRITER_V5_PRODUCTS` 상품에만 넘긴다. 1·2회 시도는 작가(예산 480초 < lease 10분), 3회 시도(SQL의 deterministic_fallback 차례)는 LLM 없이 결정론. 결제 경로는 장 저장 테이블이 없어 끊기면 lease 만료 뒤 다음 시도가 처음부터 쓴다(새 migration 없음).
11. **실제 테스트 결제 대신 확정 직후 주입(B)**: 원본 `.env.local`의 토스 키 2개는 test_로 시작하지만, confirm API는 Toss 결제창(브라우저)이 발급한 paymentKey만 받는다. 이 환경에 브라우저 자동화가 없어 결제창을 거칠 수 없으므로 지시의 대안(결제 확정 직후 단계부터 주입)을 썼고, 비밀키는 복사하지 않았다. 확정 RPC·워커 라우트·책 페이지는 실제 로컬 서버·로컬 DB로 탔다.
12. **결제 워커 개발 모드 RSS 상한**: next dev RSS 약 6GB라 결제 배치가 메모리 상한(1.25GiB)에서 즉시 503을 냈다(이용권 워커와 같은 함정). 개발 모드에서만 `PAID_WORKER_MAX_RSS_MB`로 올린다(운영 값 그대로). 같은 김에 dev:v5 관리 구역 표지의 괄호를 정규식에서 이스케이프하지 않아 실행마다 구역이 늘던 P3 버그를 고쳤다.
