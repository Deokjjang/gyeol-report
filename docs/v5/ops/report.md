## 3. 알림 통로 구조와 누락 0 근거

구조

```
payment_orders.status 변경 ─┐                      ┌→ 1) pg_net 깨우기: POST /api/ops/notify-wake (내용 없음, 분당 30회 제한)
order_requests 새 줄 ───────┼→ 트리거(넣기만) → ops_notifications ─┤        └→ 응답 뒤 대기표 비우기(after)
                            │   (dedupe_key 고유)                  └→ 2) 1분 예비 크론 /api/internal/ops-notify
1분 크론 「미발행」·「누락 보충」┘                                         미발행 감지 · 누락 보충 · 비우기 · 처리 메시지 정리 · 12시간 재알림 · 웹훅 설정
```

- 트리거 3개(`ops_notify_payment` · `ops_notify_request` · `ops_notify_wake`)는 대기표에 **넣기만** 한다. 넣기 함수는 예외를 삼키므로(`exception when others` → warning) 대기표가 고장 나도 결제·환불·문의 저장은 그대로 진행된다(시험: 대기표 제약을 일부러 깨도 결제 상태 `paid`).
- 대기표 내용(payload)에는 id만 담는다(주문·문의 id). 보낼 때 서버가 그때의 사실(금액·상품·책 상태·열람 수)로 메시지를 만든다. 사주 입력값·이름·이메일·생년월일은 메시지에 넣지 않는다.
- 같은 건은 한 번만: `dedupe_key` 고유(`pay:<주문>`·`refund:<주문>`·`req:<문의>`·`unpub:<주문>`·`nfail:<줄>`). 보내기는 `claim`(90초 잠금, `skip locked`) → 전송 → `sent`. 깨우기와 크론이 동시에 돌아도 한 줄은 한 번만 잡힌다.
- 재전송: 실패하면 1·2·4·8·16·32·60·60…분 뒤 다시. 10번 실패하면 남겨 두고 처리 봇에 「🚨 알림이 10번 실패했어요」 경고 + `/pending`에 표시.
- 깨우기 주소는 운영 설정(`ops_settings.notify_wake_url`)에 서버가 스스로 적는다(https + `/api/` 경로만 허용). 운영 DB에 비밀값을 두지 않는다 — 깨우기 주소는 내용을 받지 않고 대기표만 비우므로 인증이 필요 없다(남이 불러도 대기표를 비울 뿐, 분당 30회 제한).

### 10-6 실전 시험 결제 때 Purchase 확인 방법(덕짱님)

Purchase는 두 갈래가 **한 줄의 대기표**(`meta_conversion_outbox`, 주문당 1줄)를 같이 쓴다. 그래서 event_id가 처음부터 하나다(`purchase_` + md5(`gyeol:paid-order:` + 주문번호)).
- 서버: 결제 완료 트리거가 그 줄을 넣고, 5분 크론이 CAPI로 보낸다 → `sent_at`.
- 브라우저: 결제한 그 브라우저가 5초마다 서버에 물어 같은 줄을 받아 픽셀로 보낸다 → `browser_dispatched_at`.

**준비(결제 전에, 결제할 아이폰 사파리에서)**
1. 로그인한 상태로 화면 맨 아래 「광고 설정」 → 세 항목 체크 → 「동의하고 허용」.

   - 예전에 거부·닫기를 했어도, 이번 동의가 가장 최근 기록이면 된다. 다른 기기에서 나중에 거부하면 넣지 않는다.
2. 그 브라우저에서 결제한다(7절 1번). 결제 완료 화면이나 서재를 **1분쯤 열어 둔 뒤** 다음 단계(환불)로 간다.
   - 브라우저 쪽은 결제 10분 안, 환불 전에만 받는다. 바로 환불하면 서버만 남는다.

**확인(결제 5분 뒤, 읽기 전용 — Claude Code에 요청하시거나 Supabase SQL 편집기에서)**

```sql
select order_id, event_id, state, sent_at, browser_dispatched_at,
       event_id = 'purchase_' || md5('gyeol:paid-order:' || order_id) as id_rule
from meta_conversion_outbox where event_name = 'Purchase'
order by occurred_at desc limit 5;
```

- 결제마다 1줄, `id_rule` = true.
- `sent_at`가 있으면 서버 전송 성공(Meta가 받았다고 답함). `browser_dispatched_at`가 있으면 그 브라우저가 **같은 event_id**로 픽셀을 보냈다.
- 줄이 없으면 동의 기록에 회원이 안 붙은 것이다(준비 1을 로그인 전에 한 경우). 이때는 결제 완료 화면 경로가 넣는다.
- `browser_dispatched_at`만 비면 결제 완료 화면을 너무 빨리 닫았거나 환불이 먼저 된 것이다.
