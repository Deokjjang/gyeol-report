## 3. 알림 통로 구조와 누락 0 근거

구조

```
payment_orders.status 변경 ─┐                      ┌→ 1) pg_net 깨우기: POST /api/ops/notify-wake (내용 없음, 분당 30회 제한)
order_requests 새 줄 ───────┼→ 트리거(넣기만) → ops_notifications ─┤        └→ 응답 뒤 대기표 비우기(after)
                            │   (dedupe_key 고유)                  └→ 2) 1분 예비 크론 /api/internal/ops-notify
1분 크론 「미발행」·「누락 보충」┘                                         미발행 감지 · 누락 보충 · 비우기 · 처리 메시지 정리 · 12시간 재알림 · 웹훅 설정
```

- 트리거 3개(`ops_notify_payment` · `ops_notify_request` · `ops_notify_wake`)는 대기표에 **넣기만** 한다. 넣기 함수는 예외를 삼키므로(`exception when others` → warning) 대기표가 고장 나도 결제·환불·문의 저장은 그대로 진행된다(시험: 대기표 제약을 일부러 깨도 결제 상태 `paid`).
- 대기표 내용(payload)에는 id만 담는다(주문·문의 id). 보낼 때 서버가 그때의 사실(금액·상품·책 상태·열람 수)로 메시지를 만든다. 사주 입력값·이름·이메일·생년월일은 메시지에 넣지 않는다.
- 같은 건은 한 번만: `dedupe_key` 고유(`pay:<주문>`·`refund:<주문>`·`req:<문의>`·`unpub:<주문>`·`nfail:<줄>`). 보내기는 `claim`(90초 잠금, `skip locked`) → 전송 → `sent`. 깨우기와 크론이 동시에 돌아도 한 줄은 한 번만 잡힌다.
- 재전송: 실패하면 1·2·4·8·16·32·60·60…분 뒤 다시. 10번 실패하면 남겨 두고 처리 봇에 「🚨 알림이 10번 실패했어요」 경고 + `/pending`에 표시.
- 깨우기 주소는 운영 설정(`ops_settings.notify_wake_url`)에 서버가 스스로 적는다(https + `/api/` 경로만 허용). 운영 DB에 비밀값을 두지 않는다 — 깨우기 주소는 내용을 받지 않고 대기표만 비우므로 인증이 필요 없다(남이 불러도 대기표를 비울 뿐, 분당 30회 제한).

## 7. 실전 시험 순서(덕짱님용)와 결과

배포 뒤 30분 확인(6절)이 끝나면 시작한다. 결제·환불은 덕짱님이 직접 한다(Claude Code는 결제·환불을 하지 않는다). 문제가 보이면 그 자리에서 멈추고 보고한다.

1. **결제 2건** — 덕짱님 계정으로 「나라는 사람」 3,900원을 토스페이로 1건, 카카오페이로 1건 결제한다(책 2권은 열지 말고 둔다 — 열람 0회여야 ★환불이 나온다).
   - 매출 봇: 건마다 「💳 3,900원 · 나라는 사람 / 토스페이(또는 카카오페이) · 신규 또는 재구매(이 계정의 첫 유료 결제만 신규) · 시각 / 오늘 N건 · 금액」.
   - 서재: 증정 이용권이 결제마다 1장(이벤트 기간). 증정 이용권은 쓰지 말고 둔다(환불 때 회수 확인용).
   - 메타 구매 이벤트는 Events Manager에서 덕짱님이 확인.
2. **처리 봇 환불(A건)** — 서재에서 A건 「문의·환불 요청」 → 「책이 안 나오거나 안 열려요」 → [접수].
   - 서재: 「접수됐어요. 확인 후 이 책 카드에서 결과를 알려 드릴게요.」, 버튼이 「접수됨」.
   - 처리 봇: 「📮 책이 안 열려요 · GR-○○○○ / 나라는 사람 · 3,900원 · 결제수단 · 시각 / 책 완성 · 열람 0회 · 기기 / 이 계정 결제 N · 환불 N · 이 결제 증정 이용권 미사용」 + [★환불] [다시 만들기] [안내].
   - [★환불] → 같은 메시지가 「GR-○○○○ 3,900원 환불 · 비밀번호를 보내 주세요 (2분)」 + [취소] → 답장 칸에 관리자 화면 비밀번호를 보낸다 → 봇이 그 메시지를 바로 지운다.
   - 결과: 메시지가 「✅ 환불 완료 3,900원 · GR-○○○○ · 시각 · 이용권 1장 회수」로 바뀌고 버튼이 사라진다 → 매출 봇 「↩️ 환불 3,900원 · 나라는 사람 · GR-○○○○ / 오늘 순매출 3,900원」 → 서재 카드 「환불됐어요. 결제수단에 따라 바로 또는 영업일 3~5일 안에 돌아가요.」 → 서재 이용권이 1장 줄어든다(회수) → 결제 앱에서 취소 확인.
3. **관리자 화면 환불(B건)** — `/admin/orders/GR-○○○○`에서 기존 절차로 환불 → 매출 봇 「↩️ 환불 …」(다른 경로 확인). 처리 봇에는 아무것도 오지 않는다(문의가 없으므로).
4. **명령** — 매출 봇 `/today`(결제 2 · 환불 2 · 순매출 0원), 처리 봇 `/pending`(남은 건 없음).
