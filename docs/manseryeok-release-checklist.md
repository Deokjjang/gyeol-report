## 3. 기존 Book 열람 확인

기존 Book은 저장된 스냅샷으로만 그린다. 신살 수정을 병합하면 읽을 때 원국 표를 저장 버전(`saju-calendar-kst-v2`) 규칙으로 다시 만들어 비교한다.

1. ☐ 배포 전: `pnpm vitest run tests/unit/saju/legacyBookProtection.test.ts tests/unit/saju/shinsalVersioning.test.ts` PASS.
2. ☐ 배포 전: 실제 고객 Book 표본을 열람만 해서 확인할지 결정한다(운영 DB 읽기 권한 필요, 쓰기 금지).
3. 배포 직후 운영에서 기존 Book 5건 이상(가능하면 6개 상품 모두, 서머타임·근사 시간대·시간 모름 고객 포함)을 연다.
   - ☐ `/reports/[id]`, `/r/[token]` 모두 열린다("리포트를 준비하고 있습니다" 없음).
   - ☐ 만세력 표 아래 **보정 문구가 없다**(기존 리포트에는 나오면 안 된다).
   - ☐ 근사 시간대 고객의 라벨이 예전 그대로다(예: `묘시 05:00~06:59`).
   - ☐ 신살 칸이 예전과 같다(망신·고신·과숙 위치 변화 없음).
4. ☐ 배포 후 24시간 동안 `/api/internal/report-retry`(GET) attention 목록과 quarantine 건수가 늘지 않는다.
