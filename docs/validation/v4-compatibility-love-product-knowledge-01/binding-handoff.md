# 후속 근거 연결 인수 — 구현하지 않음

1. 두 사람의 actual person ID, 원국 atom, MBTI node, 개인 Fusion의 양쪽 root를 각각 확인한다. sourceRegistry는 지식 주소이며 실제 검출 사실이 아니다.
2. canonical 관계는 기존 producer가 발급한 ID·kind·참여자·기둥 위치·지지만 사용한다. 64개 전통 표의 membership은 검출 결과가 아니다. 미지원 30조합은 보류한다.
3. A→B는 B.dayMaster(viewer), A.dayMaster(target)이며 행동 발신자는 A다. 역방향은 별도 기존 결과를 사용한다. 동일 십성이면 없는 차이를 만들지 않는다.
4. MBTI Pair 256방향은 reference-only. forward/reverse sourceCoverage·미검증 계보를 보존하고 각 절의 행동 주어를 검토한다. 한쪽 미상은 Pair와 해당 개인 Fusion을 보류한다.
5. 실제 signed axis를 두 소유자별로 검증한다. 같음=성공, 반대=갈등/보완이 아니다. facet은 관찰 질문이며 독립 Evidence가 아니다.
6. 두 개인 Fusion을 하나의 Pair 점수로 합치지 않는다. 같은 root의 natal/MBTI/Fusion 재사용을 독립 근거로 중복 집계하지 않는다.
7. CH09 모든 문단에 actuallyDisplayed ledger가 필요하다. 동일 두 사람·유형·방향·실제 source의 호환 부분만 회수한다. 미도입이면 생략/보류하고 새 운세로 채우지 않는다.
8. CH08은 실제 도입한 CH07 또는 방향별 부담의 조건을 확인하고 각자 바꿀 행동·공동 합의·재확인 시점을 구분한다. 강요·폭력·감시에는 화해를 강제하지 않는다.
9. 후보의 실제 조건이 불충족이면 withhold. 이름 교환, 상대 유형 추정, 시주 보충, 과거 사건 창작을 금지한다.
10. 실제 연결은 별도 승인 작업이다. bindingProposalTypes.ts는 타입 선언뿐이며 resolver/selector/score/Book 변경을 포함하지 않는다.

## 미해결 범위

80개 후보가 모든 256유형 방향×36문단 조합을 채운다는 보장은 없다. 256은 원문 전체 source review다. 구체 후보에서 사용하는 Pair 원천은 10개, 개인 Fusion은 5개다. 나머지 자료는 후속 정확한 조건 연결과 문체 검토가 필요하다. 다른 6개 관계 DB·기간 궁합 해석·새 관계 producer·회수 엔진·선택 편중 검증은 이번 작업에 포함하지 않았다.
