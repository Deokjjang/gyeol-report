# Handoff to V4-KNOWLEDGE-SOURCE-VERIFICATION-01

Run `node scripts/knowledge-catalog/compile.mjs [output-directory]` from the worktree with frozen dependencies installed. Default output is this validation directory. The CLI executes trusted repository data exports offline, blocks fetch, and uses the same modules as the tests. It is a developer tool, not a public API or arbitrary-input sandbox. Do not expose its root/config/loader to an HTTP request.

`compiler-config.json` is the explicit family/data adapter. Twenty research folders are discovered independently and checked against it; unconfigured families, unreadable exports, count drift and duplicate catalog keys fail the CLI. Foundation source slots are separate. The raw registries remain at original paths; catalog and edge shards store locators, identity, conditions and status rather than copied complete source records. The top catalog/graph files are shard indexes. No route imports this compiler, TypeScript tooling or research arrays.

Catalog keys hash the versioned namespace, file, export and original identity; foundation slots additionally retain source addresses to distinguish homonymous traits/alias views. Keys do not constitute personal Evidence. Original source IDs, claim/expression IDs and locators remain separately readable. All acquisition snapshots use the base commit version; original nested source versions remain in their source contracts and resolved reference locators. Changes to a source array's positions require regeneration and integrity review.

Hash schemes follow existing tests: `recordSha256` uses insertion-order JSON; MBTI Pair `sha256` uses recursively sorted JSON; Fusion traits use insertion-order `sha256` plus raw plainKo hash; MBTI research `sourceMeaningSha256` hashes plainKo; 40-character source versions identify known Git commits while 64-character source versions identify file bytes. No automatic fallback between schemes. No network source is revalidated by this offline compiler.

Use `unresolved-references.json` and manifest issues as the verification queue. Each occurrence retains its affected catalog key, reference field, original target and exact reason. Resolve aliases only against concrete sources, inspect original producer support and version/hash, then review each application. Do not edit original research during this delivery or treat an inherited audit snapshot as the original web page. Hash integrity does not make the content correct.

Independent dimensions and unapproved status are in `knowledge-status-matrix.json`; original full records are recoverable by locator/hash. Product/category indexes are declarations and preserve counterconditions; they are not eligible candidates. `selective-index-design.json` is an offline lookup design for future selective retrieval. Runtime integration must load a small approved shard by product/domain/condition after verifying all twelve gates; it must never linearly scan the entire research tree per customer request.

Remaining work: source/alias verification; ambiguous target IDs; documentary/external references without original locators; missing qualified fragments; domain crosswalk review; independent meaning/linguistic review; producer/owner/direction/time validation; explicit customer approval. Then separately authorize Evidence Graph, candidate binding, global planning, Korean realization and release validation. No next stage executes automatically.
