# Career Specialist Engine 인수 계약

OFFLINE_IMPLEMENTED. 이 문서는 향후 인수용이며 실제 고객 배정·Writer·Planner 구현이 아니다.

## 현재 API

1. 원래 Catalog/Source/Semantic/Graph 계약으로 ProductSpecialistFoundation을 준비한다.
2. CareerSpecialistEngine(foundation).index에서 원래 192 Material·180 Question 및 SourceKey·조건·전문 연구를 조회한다.
3. diagnose(request, optionalPreparedFoundationResult)는 Career/null relationship과 실제 producer packet만 받는다. 기존 Graph·원고·추천 결과를 변경하지 않는다.
4. result의 기존 12 gate receipt, 정형 추가 관측, source/hash, job/직무/경제/학습/proof/회수 차단, 의미 관계와 root index를 인수한다.
5. 실제 ranking null, customerSelectionRun false, 실제 승인/eligible/claim/Book 변경 0을 전제한다.
6. selectCareerSynthetic은 자신의 Registry·Graph·승인·관측 Context가 검증된 private session만 받는다. 실제 연구 result는 입력할 수 없다.

## ID와 상태의 구분

- SourceKey와 Registry sourceId는 연구 참조다. 원래 Catalog ID, native producer ID, Graph node, canonical root와 서로 다르다.
- MBTI qualified alias는 타입/영역/파일/record hash로 실제 원본 trait까지 연결한다. 이름이 비슷한 trait을 쓰지 않는다.
- JobStatus enum 참조는 입력 schema 정의이며 개인의 계산 근거가 아니다.
- 정확한 native 십성 존재 관측도 원래 자연어 조건·위치·반례·Domain·승인 검토를 해결하지 않는다.
- parser workFunction은 현재 setting 관측이다. JobResearch와 DetailApplication의 업무 설명은 개인 수행 능력이 아니다.
- 실제 추천 결과의 ID/순서/이유와 일반 직무 연구, 실제 proof/root 호환성, 전문 응용 승인을 구분한다.
- 부분 proof를 complete로 올리지 않는다. 미해결 원본 MBTI hint 3건은 유사 trait으로 보완하지 않는다.
- 실제 돈·자격·학력·숙련·계약·직원·권한·경험은 입력 없으면 UNKNOWN이다.

## 재사용·회수·배정 경계

- 실제 연구의 의미 identity 승인 0. 같은 root나 다른 문구/질문만으로 독립 의미를 승인하지 않는다.
- Reader CH01~CH09와 K1~K10은 번호 대응하지 않는다. K9는 새 추천 순위 생산자가 아니다.
- 기존 Career positive facet cap 4와 chapter guard/risk/recall 예외를 원래 코드 범위로 유지한다.
- 기존 root atom 사용 수는 정렬 조건이며 hard cap 3이 아니다. canonical root ↔ Release atom 및 연구 ↔ Release facet bridge는 미검증이다.
- K duplicateGroup/semanticTheme와 Reader 예산은 별도 계약이다. 연구 facet별 새 예산을 만들지 않는다.
- 합성 root 통계는 새 primary 정보 사용량이다. 회수의 support 참조가 새 primary 사실을 추가하지 않는다.
- CH09는 실제 표시, 같은 owner/type/root/meaning/claim, 호환 상태/함수/상세 Context/질문과 원래 선행 의미가 필요하다. 계획은 ledger가 아니다.
- 실제 고객 ledger는 이 엔진이 발급하지 않는다.

## 실제 고객 연결 전 필요 사항

1. 원래 의미·Source Scope·Domain·조건·반례 및 운영자/고객 승인 계약.
2. typed 자연어 조건/group/producer 지원. 없는 관측·Fusion rule·직무 능력을 생성하지 않는다.
3. legacy recommendation/avoid proof의 완전한 provenance와 실제 root 호환성.
4. 위 identity/budget/Reader bridge 검증.
5. 실제 rendering/publication에서 발급된 display ledger.
6. 현재 Release 길이·일반 문장·fallback 및 별도 Writer 품질 감사.
7. 명시적인 후속 작업 지시.

합성 전역 선택의 성공은 실제 고객 전문 원고의 완성이나 판매 승인이 아니다. 실제 17 Book/102 digest와 기존 Runtime·계산·추천·원고·연구 원문은 보존한다.
