## Ancestry and policy behavior

`graph.ts` indexes CatalogKey, original ID, family source key, Domain, Product and Relationship. REFERENCES, REQUIRES and REUSES_SOURCE follow original roles. RELATED_TO/CAN_APPLY_TO, documentary references, future requirements and definition declarations are retained without promotion to required personal calculation ancestors. DFS uses memoization and cycle detection.

Existing source groups remain separate. Conditional displayed alternatives are not flattened into a universal AND. Each alternative is checked for missing sources, owner/type conflicts and prohibited ancestry; actual displayed compatibility remains pending. ALL_DIRECT groups retain their declared AND requirement. A source declaration is never a real person's calculated Fact Root.

Existing `relationshipProductView.ts:47` permits a candidate when some source node IDs are allowed. Static inspection therefore does not establish that the present customer runtime enforces the new all-required-ancestor policy for every mixed source candidate. This task does not modify that runtime. The offline overlay identifies CHILDREN ancestry and records a mandatory future all-ancestor gate; customer-runtime repair/connection must be separately scoped before any affected use is approved.
