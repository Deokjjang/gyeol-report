기준은 `aa82faa271dad0a03604c859c8bbb0161aa711c6`이며, 요청된 지속 Worktree 및 `v4/product-wide-editorial-upgrade-01`에서 작업했다. 앞선 최종 조립의 궁합 36문단 선택 및 연애 배정 소진 복구를 `f15bc25e78a4434c91441946799bcfbf6bbcd998`로 먼저 가져왔다. 아래 원고 비교의 변경 전 기준에도 이 기능 복구가 포함된다.

## 실제 경로 및 수정

`generateV4ShadowReport → validateV4Publication → projectBook → BookReading/BookReader`와 기존 `/dev/content-review`를 그대로 사용했다. 별도 Writer, 별도 연구 DB 또는 검수 HTML을 만들지 않았다.

- `contentMbti`: 기존 16유형의 검토 문장을 실제 trait ID·원본 값·도메인·sourceCoverage에 맞춰 재사용한다. 기존 DB의 ESFP `romantic_surprise`, `introvert_bridge` 고객용 strongLine 두 개도 명시적으로 연결했다. 원천 DB는 수정하지 않았다.
- 종합·커리어: 보고서 안에서 사용한 MBTI 노드를 기록하고 같은 적합도에서는 덜 쓴 근거를 선택한다. 단순 축 조언으로 평준화되던 금전·업무 자료를 해당 자료의 문장으로 표현한다.
- 연애·궁합: 기존 signed-axis와 양쪽 Fusion 출처 검증을 유지하면서 구체적인 기존 MBTI 행동을 사용한다. 궁합의 다섯 비연애 유형에서 반복 문구 진단이 사라졌고 36문단을 유지했다.
- `contentSynthesis`: 장의 실제 근거에 연결되는 MBTI 읽기를 우선한다. 무조건 같은 방향이라고 묶는 연결문 대신 해당 원국 근거의 기존 쉬운 정의를 사용하고, 이미 설명한 정의는 반복하지 않는다. 대운의 기존 원국/대운 구분 및 조건부 적용을 유지한다.
- `readerCopy`: 기존 displayDictionaries를 사용해 확인된 천간·지지·60간지만 한글(한자)로 표시한다. 이름·ID·다른 한자·이미 병기된 표를 보호한다. 확인된 읽기에 붙은 조사만 기존 한국어 유틸리티로 고친다. `己丑로`는 `기축(己丑)으로`, `乙으로`는 `을(乙)로`가 된다.
- 날짜/시각은 렌더링 시에만 한국어로 표시한다. 절기 기준 및 정확한 시각·초 단위 원본은 유지한다. 잘못된 날짜나 알 수 없는 형식은 임의로 보정하지 않는다.
- 각주: 본문 마커 중복·잘못된 참조를 걸러내고 본문/마커, 이름/설명 사이에 공백을 둔다. 수동 번호를 제거하고 네이티브 목록 번호 하나를 사용한다. 실제 높이 0이던 버튼은 16px 박스와 기존 44px hit area를 사용하도록 수정했다. 설명·레이블·팝업은 보존했다.

## 계산·근거·저장본 보호

이전 지속 Worktree의 같은 17개 payload/clock을 실제로 다시 실행해 비교했다. 계산, 명리/MBTI 표, 선택된 원천 자료, 궁합 지수·방향·인물 프로필, 교운 시각 및 연도/월 범위의 서명이 모두 일치했다. 신규 원고와 contentDigest/새 Book digest는 의도적으로 달라진다. 과거 구매 스냅샷을 재생성하거나 덮어쓰지 않는다.

기존 역사적 golden JSON은 보존했다. 이번에 바뀐 전체 원고의 출력 잠금은 `tests/fixtures/product-wide-editorial-01/output-locks.json`으로 분리했다. 원고의 새 해시와 별개로 이전 계산/자료 서명을 계속 검사한다. 실제 원고 변화 때문에 실패한 과거 전체 해시 동일성 검사, 한자 원문과 화면이 동일해야 한다던 검사, 반복 진단이 반드시 있어야 한다던 검사를 새 계약에 맞췄다. 안전성 부정 사례는 유지했다.

## 브라우저 확인

기존 입력 화면에서 6권을 생성하고 132페이지를 끝까지 넘겼다. 대표 입력의 본문 누락, 가로 넘침, Source/Root ID·ISO 시각 노출은 확인되지 않았다. 각주 설명 창, 일반 텍스트/HTML 복사, 6권 새로고침 후 저장본 재열람을 확인했다. 처음 궁합 자동 입력에서 비어 있던 A 생년월일은 입력 검증으로 차단됐고, 날짜 입력을 확정한 후 정상 생성됐다. 제품 코드는 이 입력 오류 때문에 바꾸지 않았다.

복사 전 DOM에는 네이티브 ol과 수동 `1.` span이 공존했다. Chrome 일반 텍스트에서 `1. 1.` 자체는 변경 전에도 재현되지 않았다. 변경 후에는 일반 텍스트와 HTML 모두 중복 번호가 없고 설명 공백을 확인했다. 각주 버튼은 변경 전 실제 높이 0, 변경 후 16px이며 실제 클릭으로 설명 창이 열렸다.

세운의 실제 절기 구간에서 `2026-01-05T...` 대신 `2026년 1월 5일 17시 23분 10초`와 무자(戊子)/기축(己丑)를 확인했다. 원본 시각은 그대로다. 한글 병기로 긴 목차/시기 문구가 더 길어지는 점은 있으며, 화면 밀도와 최종 문체는 후속 상품별 직접 검수 대상이다. 이번 확인을 전 상품 판매 품질 PASS로 해석하지 않는다.

검수 화면: http://localhost:3193/dev/content-review

로컬 전용 차단은 유지했다. 검수 자료는 브라우저 전용 저장소이며 운영 DB·주문·결제·쿠폰·이벤트를 사용하지 않는다. 원격 공개 QA 화면은 추가하지 않았다.
