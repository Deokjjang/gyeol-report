  - A 책임: 재량·점검·지원 응답 시점 명시; B 가능 행동: 예외 조건과 현재 상태 공유

  - 장면: 가상: 검증 자료 작성자를 기록하고 다음 부탁은 따로 확인; 반례: 확인되지 않은 실적은 후보로도 만들지 않음

  - 역할: 조정할 행동 → 모호한 평가어를 산출물 행동으로 바꾸기 / B의 필요 → B에게 필요한 수정 시간·기준을 확인하고 인격 추정 배제 / 확인할 실천 → 다음 버전에서 확인할 항목과 A의 검토 응답 시점을 정함 / A→B 가능성 → B가 무엇을 고치고 언제 끝낼지 예측할 여지

  - 장면: 가상: 한 번의 수정 범위를 정해 다음 검토; 반례: 평가권·실적 판단은 별도 사실 필요
  - 별도 정보: 위임 범위와 다른 수정 종료 인터페이스; 권한 질문: 다음 검토에서 어느 항목을 확인하면 끝나나요?

## CH06.P1 — B는 A에게 어떤 자극을 주는가

질문: A 수신 십성과 B의 실행 정보는 어떤 질문인가?

- mrpr:material:CH06.P1:report-to-manager-reality-check: B가 계획과 다른 사실을 A에게 보여주는 자극
  - 역할: B→A 영향 → B의 실제 검토 원천과 A의 큰 구조 원천을 구분하는 B→A 후보 / 받는 사람 기준 십성 → 수신 A 일간으로 B 일간을 본 실제 상관 정의는 반항적 팀원이라는 판정 아님 / 다른 방향 행동 → B가 계획 가정과 달라진 수치·영향을 정리하는 가상 보고 / A에게 남는 의미 → A에게 남는 것은 체면 도전보다 수정 판단에 필요한 정보일 수 있음
  - A 책임: 정보를 검토하고 변경 여부·지원 결정; B 가능 행동: 관찰·영향·필요 결정 구분
  - 긍정: 계획 변경의 필요를 발견할 여지; 위험: 사실 보고를 인사 평가에 대한 도전으로 해석
  - 팩폭: 상사 판단에 다른 정보를 주는 것은 상사 책임을 대신 지는 일이 아니다; 반전: 팀원의 이견이 목표를 지키려는 행동일 수도 있다
  - 장면: 가상: 일정 가정과 실제 작업 시간을 비교; 반례: B 같은 사람 Fusion root 없으면 해당 지원 보류
  - 별도 정보: A→B 기준 자극과 다른 실행 사실의 역방향; 권한 질문: 이 차이에서 어떤 계획 변경을 검토해 주실 수 있나요?
- mrpr:material:CH06.P1:report-to-manager-customer-observation: B의 가까운 반응 정보와 A의 판단
  - 역할: B→A 영향 → B가 즉각 요구를 알아채는 실제 원천이 있을 때만 후보 / 받는 사람 기준 십성 → A 수신 실제 식신 정의는 B의 보고 정확성·고객 실적을 보장하지 않음 / 다른 방향 행동 → 관찰한 문의·빈도·범위와 B의 해석을 나누어 A에게 전달 / A에게 남는 의미 → A는 제한된 반응을 전체 고객 의견으로 확대하지 않고 확인할 수 있음
  - A 책임: 표본 범위·추가 확인·대응 우선순위 판단; B 가능 행동: 관찰 사실과 추정·제안 구분
  - 긍정: 빠진 현장 질문을 얻을 여지; 위험: 눈앞 반응을 전체 판단으로 확정
  - 팩폭: 한 사람의 급한 반응이 모두의 요구는 아니다; 반전: 공감 정보도 범위를 적으면 판단 자료로 더 쓰기 쉬울 수 있다
  - 장면: 가상: 반복 문의와 미확인 원인을 분리해 보고; 반례: 실제 직업·고객 관계를 만들어내지 않음
  - 별도 정보: 수치 불일치와 다른 반응 정보의 범위; 권한 질문: 확인한 반응의 범위와 추가 확인을 나눌까요?

## CH06.P2 — B가 A에게 주는 좋은 영향

질문: B의 대안·용량 정보는 언제 관리 결정을 돕는가?

- mrpr:material:CH06.P2:report-propose-bounded-method: B의 대안이 A의 검토를 돕는 조건
  - 역할: 도움 되는 강점 → 새 선택지와 비교 기준을 함께 주는 강점 후보 / 독립적 근거 → 각자 실제 개인 원천과 A 수신 십성 정의를 별도 확인 / 관계별 장면 → 가상 새 방법 제안에서 예상 장점·검증 방법·되돌림 조건을 제시 / 발휘 조건 → A가 권한 안에서 시험 범위를 판단하고 필요한 자원을 결정해야 함

  - 팩폭: 좋은 안을 냈다고 승인권까지 가진 것은 아니다; 반전: 작은 시험 제안이 전면 변경보다 검토를 쉽게 할 수 있다
  - 장면: 가상: 기존 기준을 지키는 작은 시험안; 반례: 성과·예산 효과는 미확인 추정으로 표시

  - 팩폭: 팀원이 시간을 공개해도 없는 여력은 생기지 않는다; 반전: 한계 보고가 부탁을 거절하는 말보다 계획을 지키는 자료일 수 있다
  - 장면: 가상: 추가 요청과 기존 마감의 충돌을 표로 표시; 반례: 실제 근로조건·법률 판단은 별도
  - 별도 정보: 아이디어와 다른 배분 정보; 권한 질문: 두 작업이 겹칠 때 우선순위를 정해 주실 수 있나요?

## CH06.P3 — B의 행동이 A에게 부담이 되는 순간

질문: B의 늦은 보고·질문은 언제 결정 공백이 되는가?

- mrpr:material:CH06.P3:report-unclear-risk-timing: 완성본을 기다리는 보고가 A의 결정 시점을 놓칠 위험
  - 역할: 부담 행동 → B의 늦은 몰입과 A의 빠른 판단 원천이 모두 확인된 조건 / 검증된 차이 → 속도 차이는 실제 지연·태만 사실이 아님 / 의도와 경험 → B는 확정하고 말하려 해도 A는 지원 판단에 필요한 상태를 못 받을 수 있음 / 악화 조건 → 불확실 보고마다 책임을 몰아주면 보고가 더 늦어질 위험
  - A 책임: 보고 통로·시한·지원 응답을 명확히 함; B 가능 행동: 상태·영향·다음 확인을 전달
  - 긍정: 중간 정보로 지원 필요를 확인할 여지; 위험: 보고 지연 원인을 B 성격만으로 설명
  - 팩폭: 보고 의무가 있어도 상사의 불확실성 수용 책임은 없어지지 않는다; 반전: 모른다는 범위를 일찍 알리는 것이 더 정확한 보고일 수 있다
  - 장면: 가상: 완료 전 막힘과 다음 확인 시점을 공유; 반례: 안전한 직접 보고가 어렵다면 적절한 지원 확인
  - 별도 정보: BA 정보 시점의 비용; 권한 질문: 확정 전에도 어떤 위험을 먼저 알려야 하나요?
- mrpr:material:CH06.P3:report-question-as-final-decision: 질문이 늘어도 승인 책임은 넘어가지 않음
  - 역할: 부담 행동 → B가 이유를 계속 묻고 A가 기준을 지키려는 원천을 확인 / 검증된 차이 → 검증된 차이는 질문 범위이며 실제 불복종·통제 이력은 미확인 / 의도와 경험 → B는 이해하려고 질문해도 A는 이미 끝난 결정을 다시 논의한다고 받을 수 있음 / 악화 조건 → 질문·대안·승인 요청을 섞으면 필요한 결정이 불명확해짐
  - A 책임: 결정 근거와 변경 가능 여부 설명; B 가능 행동: 확인 질문·제안·승인 요청 구분
  - 긍정: 질문의 목적을 분명히 할 여지; 위험: 팀원이 질문을 포기해 결정 근거가 숨겨짐
  - 팩폭: 설명 질문을 줄이는 것만으로 관리 결정이 좋아지는 것은 아니다; 반전: 질문 범위를 정하면 권한과 이견이 함께 남을 수 있다
  - 장면: 가상: 기준 확인 질문과 변경 요청을 따로 제시; 반례: 실제 확정 결정·권한은 별도 확인
  - 별도 정보: 늦은 보고와 다른 질문 상태 혼동; 권한 질문: 기준 확인과 변경 제안 중 무엇으로 검토하면 될까요?

## CH06.P4 — B가 영향력을 잘 사용하는 방법

  - A 책임: 결정과 미결 항목을 답변; B 가능 행동: 사실·선택지·결정 요청을 구분
  - 긍정: 보고의 쓰임을 명확히 할 여지; 위험: 요약이 미확인 위험을 숨기는 방식이 됨
  - 팩폭: 짧은 보고는 책임 회피도 자동 승인도 아니다; 반전: 한 줄 더 적는 불확실성이 전체 보고를 더 정확하게 할 수 있다
  - 장면: 가상: 결정 필요 시각과 미확인 항목을 붙인 짧은 보고; 반례: 간결함 때문에 필수 안전 정보를 생략 불가
  - 별도 정보: BA 보고를 결정 인터페이스로 정리; 권한 질문: 이 중 상사 결정이 필요한 항목을 확인해 주실 수 있나요?
- mrpr:material:CH06.P4:report-feedback-clarification: B가 평가어를 수정 조건 질문으로 바꾸기
  - 역할: 조정할 행동 → 막연한 지적에서 관찰 항목·수정 범위를 확인하는 행동 / A의 필요 → A가 답해야 할 기준을 B가 대신 추측하지 않게 함 / 확인할 실천 → 질문할 안전이 확인된 경우 문서·개별 대화 등 적합한 방식 선택 / B→A 가능성 → A는 수정 기준·지원·재검토 시점을 더 분명하게 설명할 수 있음
  - A 책임: 행동 기준·수정 시간·지원 설명; B 가능 행동: 관찰 예시와 수정 우선순위를 요청
  - 긍정: 수정 공백을 줄일 여지; 위험: B의 말투 교정만 요구하고 공개 판단을 유지
  - 팩폭: 팀원이 질문을 잘해도 공개 인격 판단의 책임은 상사에게 남는다; 반전: 피드백을 다시 묻는 것이 거부보다 수행 의지일 수 있다

  - 장면: 가상: 다음 제출에서도 필수 항목과 검토를 분리; 반례: 같은 root·과제·실제 표시 확인 전 보류
  - 별도 정보: 공통점의 재진술보다 지속 조건 회수; 권한 질문: 완료 기준과 각자의 남은 역할을 다시 확인할까요?

## CH09.P2 — 함께 활용할 수 있는 좋은 기운

질문: 표시된 지원·개인 Fusion의 호환 의미를 어떻게 활용하는가?

- mrpr:material:CH09.P2:recall-supported-possibility: 실제 소개된 지원 가능성을 활용하기
  - 역할: 검증된 좋은 기운 → B에게 맞는 A 지원의 검증된 부분만 회수 / 근거와 의미 → 동일 A/B·AB방향·수신 십성·개인 원천·실제 표시가 필요 / 관계의 가능성 → 접근 경로·담당·시점이 확인돼야 지원 가능성으로 남음 / 현실적 활용 → 다음 막힘에도 필요한 자원과 응답을 구체적으로 요청
  - A 책임: 확인 가능한 지원·연결 책임 명시; B 가능 행동: 막힌 단계·필요 자원 설명
  - 긍정: 지원 창구를 활용할 여지; 위험: 정인을 실제 보호·성공 경험으로 표현
  - 팩폭: 지원의 좋은 기운은 권한 없는 약속을 대신하지 못한다; 반전: 상사가 답을 직접 몰라도 연결 책임을 맡을 수 있다
  - 장면: 가상: 다음 막힘에서도 지원 담당·시점을 확인; 반례: 후보·계산만으로 실제 도움 받은 이력 생성 금지
  - 별도 정보: AB 실제 지원 의미 회수; 권한 질문: 다음 막힘에 활용할 확인된 지원 경로는 무엇인가요?
- mrpr:material:CH09.P2:recall-personal-fusion: 표시된 B의 실제 정보 기여만 활용
  - 역할: 검증된 좋은 기운 → 원국·MBTI가 만난 개인 Fusion의 호환된 의미만 회수 / 근거와 의미 → B 개인의 실제 두 root·rule·context와 BA표시 이력이 필요 / 관계의 가능성 → B의 실제 검토 정보가 A의 계획 확인에 쓰일 가능성 / 현실적 활용 → 가정·관찰·결정 필요를 구분하는 현실 행동으로 활용
  - A 책임: 실제 정보를 검토해 결정·지원; B 가능 행동: 관찰·영향·미확인을 분리
  - 긍정: 정보의 설명력을 유지할 여지; 위험: 개인 Fusion을 공동 궁합 점수로 합산
  - 팩폭: 두 체계가 같은 사람을 설명해도 새 궁합 점수는 아니다; 반전: 팀원의 반례가 공동 목표를 더 선명하게 할 수 있다
  - 장면: 가상: 계획의 가정과 실제 결과를 비교; 반례: Fusion root·방향·실제 표시 없으면 보류
  - 별도 정보: 계산된 개인 연결의 출처를 보존한 회수; 권한 질문: 실제 정보가 바꾸는 가정과 필요한 결정을 구분할까요?

## CH09.P3 — 관계를 오래 지키는 선택

질문: 표시된 위임·안전 원칙을 어떤 조건에서 유지하는가?

- mrpr:material:CH09.P3:recall-delegation-principle: 실제로 소개된 결정 경계만 지속
  - 역할: 조율 원칙 → 앞서 실제 표시된 조율 원칙과 같은 인물·과제의 의미만 회수 / 개인별 이유 → A는 기준·지원 B는 수행 범위가 필요한 독립 이유 / 실천 행동 → 확인된 결정 범위·응답 책임·기한을 다음 과제에도 점검 / 지속 조건 → 과제가 달라지면 과거 합의를 자동으로 확대하지 않음
  - A 책임: 실제 범위·지원·응답을 재확인; B 가능 행동: 변경된 수행 조건을 알림
  - 긍정: 재량·승인 대기를 구별할 여지; 위험: 한 번 합의로 모든 권한 확인 완료 선언
  - 팩폭: 위임의 범위는 과제가 바뀌면 다시 물어야 한다; 반전: 좋은 원칙도 상황에 맞게 좁히는 것이 지속 조건일 수 있다
  - 장면: 가상: 다음 과제에서 승인 경계를 새로 확인; 반례: 같은 task·owner·actuallyDisplayed 확인 필요
  - 별도 정보: 강점 요약 아닌 결정 원칙 회수; 권한 질문: 새 과제에서 재량과 승인 경계가 달라졌나요?
- mrpr:material:CH09.P3:recall-safe-voice: 실제로 소개된 안전한 지원 선택을 유지
  - 역할: 조율 원칙 → 앞서 실제 표시된 조율 원칙과 같은 인물·과제의 의미만 회수 / 개인별 이유 → 관리 책임과 팀원 발언 위험은 같은 조건이 아님 / 실천 행동 → A는 안전한 질문·지원 조건 B는 가능한 통로를 확인 / 지속 조건 → 보복 우려가 있으면 직접 화해보다 적절한 별도 지원을 우선
  - A 책임: 위험을 정상화하지 않고 지원 확인; B 가능 행동: 안전·동의·선택 가능한 통로 확인
  - 긍정: 필요 지원을 확인할 여지; 위험: 관계를 오래 지키기 위해 위험을 참게 함
  - 팩폭: 관계의 지속이 안전보다 앞서는 의무는 아니다; 반전: 안전한 거리를 두는 선택도 고려할 수 있다
  - 장면: 가상: 직접 대화 전 지원 경로를 확인; 반례: 보호·안전·법적 결과를 보장하지 않음
  - 별도 정보: 실제 소개된 안전 원칙의 회수; 권한 질문: 관계를 조율하기 전 어떤 안전 조건을 확인하나요?

## CH09.P4 — 우리라는 관계의 마지막 메시지

질문: 정보·결정·기여·수정·지원의 다른 책임을 어떻게 남기는가?

- mrpr:material:CH09.P4:recall-decision-responsibility: 표시된 정보와 결정의 다른 역할로 마무리
  - 역할: 특징적인 상호작용 → B가 상태·선택지를 알리고 A가 실제 권한 안의 결정을 확인하는 상호작용 / 함께 만드는 가치 → 정보와 판단이 이어질 가능성이지 과거 성공 사실이 아님 / 기억할 기준 → 함께 기억할 기준은 수행·제안·승인·지원의 구분 / 관계별 결론 → 관리 역할 선언과 실제 권한을 확인하는 관계의 결론
  - A 책임: 결정 결과·미결·지원 책임 설명; B 가능 행동: 실행 상태·결정 필요 전달
  - 긍정: 기준을 다음 선택으로 남길 여지; 위험: 마지막 메시지에서 평등 책임으로 환원
  - 팩폭: 협력한다는 이유로 관리 책임까지 반씩 나눌 수는 없다; 반전: 서로 다른 책임을 인정하는 것이 함께 일할 조건일 수 있다
  - 장면: 가상: 다음 결정에서도 수행과 승인 담당을 확인; 반례: 실제 표시·동일 인물·과제 범위 없으면 보류
  - 별도 정보: 추상 신뢰 대신 역할별 책임 회수; 권한 질문: 함께 일하기 위해 각자 남길 책임은 무엇인가요?
- mrpr:material:CH09.P4:recall-contribution-learning: 표시된 인정·수정·지원의 좋은 방향
  - 역할: 특징적인 상호작용 → 실제로 소개된 기여 기록과 지원된 학습의 교집합만 회수 / 함께 만드는 가치 → 관찰한 기여를 남기고 수정 조건을 함께 바꾸는 가치 / 기억할 기준 → 칭찬·요청·평가·지원은 서로 다른 행동이라는 기준 / 관계별 결론 → 좋은 관계는 팀원의 적응뿐 아니라 관리 행동의 변화도 포함
  - A 책임: 기여 기록과 자기 지원 개선을 구분; B 가능 행동: 수행·미완료·지원 필요를 알림
  - 긍정: 다음 검토의 원칙을 남길 여지; 위험: 둘 중 표시 안 된 자료를 전부 회수
  - 팩폭: 고맙다는 말 뒤에 바뀌어야 할 업무 조건도 남겨야 한다; 반전: 좋은 마지막 문장은 더 참으라는 말보다 확인할 질문일 수 있다
  - 장면: 가상: 다음 검토에서 기여·수정·지원 조건을 나눔; 반례: 복수 ref는 실제 표시된 호환 subset만 회수
  - 별도 정보: 상호작용을 인정·학습의 경계로 마무리; 권한 질문: 기여·수정·지원에서 다음에 바꿀 항목은 무엇인가요?
