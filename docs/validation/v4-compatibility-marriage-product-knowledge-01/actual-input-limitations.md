# 실제 입력 한계와 보류 정책

marriage는 관계 질문의 카테고리이며 실제 혼인·동거를 확인한 상태가 아니다. compatibility payload에 가사 분담, 금융 자산, 소득, 직업, 자녀, 친족 성격·갈등, 생활 이력 필드는 없다. 내부 married 편집 값, 이름, 성별, 나이, MBTI, 사주로 이러한 사실을 만들지 않는다.

가상 맥락은 input-cases.json의 hypotheticalContext에만 있다. 실제 payload에는 넣지 않는다. U는 상태 미확인, V 공동 비용, W 가사, X 친족 행사, Y 근무·소득 변화, Z 반복 갈등의 가상 장면이다. 이 장면을 실제 경험으로 회고하지 않는다. 금액·비율·재정 자격·법률상 권리는 미확인이다.

A만 MBTI 기지면 A의 기존 개인 분석은 유지하되 새 후보가 B의 유형까지 요구하면 보류한다. B만 알려져도 대칭이다. 양쪽 미상에서는 MBTI·개인 Fusion·Pair를 만들어내지 않는다. 현재 112개 응용/회수 후보는 모두 양쪽 입력 유형을 조건으로 둔다. 따라서 양쪽 미상에서 이 새 자료로 36문단을 채울 수 있다고 주장하지 않는다. 기존 원국 기반 생성·fallback은 변경하지 않았고 D/AB 실생성 digest를 확인했다. 원국-only 결혼 응용은 추가 근거 확보 대상이다.

시간 미상에서는 시주 및 시주에만 기대는 관계를 보충하지 않는다. 확인된 다른 기둥의 기존 계산만 사용한다. '시간 없음=모든 관계 없음'도 잘못이다. E/F에서 실제 남은 refs를 검사했다.

공동 비용을 다룰 때 개인 지출의 허가제·감시를 절약 성향으로 정당화하지 않는다. 경제적 통제·위협·폭력은 같은 성격 차이로 조율하지 않고 동등 책임·강제 화해·동거를 요구하지 않는다. 실제 피해/가해자를 유형으로 판정하지 않는다.

부모 성격·자녀/양육·가족 관계가 있다는 전제도 보류한다. 친족 요청 장면은 생긴다면의 전제에서 시간·비용·정보·응답 권한만 질문한다.
