# ParentChild Global Planner Handoff

이 계약은 오프라인 후보 진단용이다. 실제 고객 후보는 customerRank=null, selection=false, eligible=0, claims=0을 유지한다.

1. `parent-child-planner-candidate-contract.json`에서 원본 ID/locator/hash, QuestionId/address, fixed role, 원래 SourceUse/조건/group 의미를 받는다. 단어에서 임의 AND/OR를 만들지 않는다.
2. 기존 `ActualBindingIndex`와 `bindKnowledgeCandidate`의12 Gate 영수증, 실제 owner·Canonical·direction·receivedTenGod, 전체 ancestry를 사용한다. 연구 SourceKey를 Producer ID로 바꾸지 않는다.
3. 실제 Parent/Child 역할 선언과 친자·법적 권한을 구분한다. Legacy Q 정규화는 V4 승인이 아니고 whole swap은 새 역할 선언이다.
4. PARENTS/CHILDREN documentary 원천, 현재 scoring projection, 실제 사람 관측, 의미 승인, 고객 승인을 각각 관리한다. 현행 scoring Domain을 확대하지 않는다.
5. 실제 발달 맥락/지원 필요는 UNKNOWN이다. YOUNG/SCHOOL/TEEN/ADULT 연구를 날짜·MBTI로 자동 선택하지 않는다. 부모 책임과 자녀 선택을 대칭화하지 않는다.
6. 각 후보의 meaning/claim 승인과 원래 반례·안전·학습/능력/성인 경계를 독립 검토한다. 실제 위험을 추정하지 않고, 명시 위험에서 강제 접촉·화해를 차단한다.
7. informationRoots와 supportingAncestryRoots를 구분한다. 원래 Root를 새 사실로 재발급하지 않는다. 아직 승인된 실제 서로 다른 응용은0이다.
8. CH05/06 방향을 예약하고 CH08 실제 회복에는 선택된 동일 CH07 의미·pair·root를 요구한다. CH09는 원래 도입 주소의 실제 표시 이력을 role/type/context/meaning/claim까지 검증한다. 실제 표시 Ledger를 발급하지 않는다.
9. FIRST_ELIGIBLE/QUESTION_FIT_FIRST/GLOBAL_CONSTRAINT_AWARE 검증은 독립 ParentChild 합성 Registry에만 적용한다. 실제 연구에 합성 승인·Display를 기록하지 않는다.
10. L/M fallback과 V 성인 경계 Writer 위험은 후속 필수 과제다. 이 단계에서 Writer/Reader/Book 연결이나 Coworker 개발을 시작하지 않는다.
