# Marriage Global Planner handoff

이 계약은 오프라인 검토용이다. 실제 customerEligible/selection/claim=0, meaningIdentity/claimIdentity/customerRank=null을 유지한다.

1. `marriage-planner-candidate-contract.json`의 원래112개 ID/locator/hash/requirements/source groups와180질문 링크를 사용한다. 기존12 Hard Gates를 먼저 실행한다. UNKNOWN은 통과가 아니다.
2. `marriage-source-matches.json`의 같은222×1군과 Source675/Actual96 관측을 분리한다. 추가 관측은 optional existence다. sourceUse AND·반례·출처·Domain 검토를 대체하지 않는다.
3. Canonical Pair와 A/B Direction identity 검증은 기존 공통 Pair Witness를 사용한다. A/B 원국·MBTI·Fusion ancestry는 소유자를 교차하지 않는다. MBTI Pair는 reference-only이고 Fusion rule ID를 만들어내지 않는다.
4. Marriage category/내부 married projection은 실제 혼인 증거가 아니다. 생활·재정·가족·자녀·동의·권한은 실제 입력 없이 UNKNOWN이다. Research fictional scene은 실제 이력이 아니다.
5. 원래 공동생활 질문·책임 단계·결정권·적용 조건·반례를 독립 검토한다. 업무 단계 enum을 매핑했다는 사실이 의미 승인이나 실제 노동시간/담당자 증거는 아니다. 성별/유형으로 담당을 배정하지 않는다.
6. informationRoots와 supportingAncestryRoots를 구분한다. 같은 root 참조로 새 fact를 발급하지 않는다. 다른 실제 응용 승인은 source/owner/condition/meaning 검토가 있어야 한다. 현재 실제 승인0이다.
7. CH05/06 방향별 자료를 예약하고 CH08 실제 회복에는 같은 pair/root의 실제 선택된 CH07 의미·동의·안전을 요구한다. 예방적 가상 절차를 실제 회복으로 취급하지 않는다.
8. CH09는 같은 인물·유형·roots·direction·meaning·claim·context·정확한 원래 소개 주소의 실제 display를 요구한다. 실제 고객 ledger는 이번 엔진에서 발급하지 않는다.
9. 합성 selection registry는 별도이며 실제 source/candidate에 승인을 주지 않는다. 세 알고리즘 비교는 fixture 결과이고 bounded search는 최적성을 보장하지 않는다.
10. 정형 worklist의 검토 우선순위는 운영자용이다. 고객 ranking/Writer/API/Book 연결은 후속 별도 승인 작업이며 이번 범위에 없다.
