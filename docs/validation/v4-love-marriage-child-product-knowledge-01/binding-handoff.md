# 후속 근거 연결 인수 문서

현재 연구는 미연결이다. 구현 범위는 static literal과 type-only 참조이며 resolver·barrel·selector·점수·fallback·writer는 만들지 않았다. `bindingProposalTypes.ts`는 후속 리뷰의 형식만 제안한다.

1. 실제 기존 producer의 Evidence ID와 source owner를 확인한다. lkr: 연구 ID는 계산 ID를 발급하지 않는다. 원국의 실제 위치·성립·반대 조건과 시주 미상을 원래 계약대로 확인한다.
2. 본인 MBTI의 원래 분야·trait·field·pointer/hash와 sourceCoverage를 보존한다. direct/inferred는 실증 수준이 아니다. 부모 본인의 parenting과 child 자료는 별도이며 상대나 아이의 사실로 전이하지 않는다.
3. 등록 Fusion의 양측 feature/type 또는 signed axis, exact source assignment, context/domain과 split 충족을 각각 확인한다. 한쪽이 없으면 결합 역할 보류. 조건부 두 원천 비교는 새 Fusion 등록이 아니다.
4. 각 문장 역할이 요구하는 원천을 개별 검토한다. 네 역할의 후보 연결이 있다는 사실은 네 역할 모두 고객에게 쓸 수 있다는 뜻이 아니다. 예를 들어 CH01.P2의 실제 MBTI 역할은 명리 정의만으로 채울 수 없다. 타입·조건이 맞는 실제 trait를 별도 확인한다.
5. 관계 상태는 여섯 실제 enum의 질문과 장면만 바꾼다. 점수·개인 core·현재 상대의 마음을 만들지 않는다. 입력하지 않은 동거 형태·혼인 기간·자녀 유무·연령은 남겨둔다.
6. 도화는 실제 성립·원래 정의·전통 상징·현대 적용·고객 승인 상태를 분리한다. 홍염의 신규 확장은 보류다. 귀인의 도움 받는 뜻을 도움 주는 능력이나 부유한 배우자로 뒤집지 않는다.
7. CH09.P1/P2의 새 긍정은 실제 source 검증이 필요하다. P3/P4는 실제 앞에서 선택·소개된 호환 가능한 의미의 일부만 회수한다. 대안 후보 전부를 한 사람의 사실로 누적하지 않는다.
8. 근거 부족은 보류한다. 허위 문장으로 길이나 36문단을 맞추지 않는다. 기존 hardErrors와 qualityIssues 구분, 8,000–10,000자 진단, 기존 유료 발행·Worker 안전 계약은 그대로 둔다.
9. 가상 장면은 조건부 예시다. 실제 경험 회고로 바꾸지 않는다. 위험한 관계에서는 화해·재대면을 의무로 두지 않는다.
10. 후속 연결은 별도 승인 작업이다. source별 사용 분포·교차 챕터 의미 중복·미상 입력의 부족을 실제 배정 로그로 측정한 뒤 판단한다. 이번에는 연결과 표현 제작을 시작하지 않았다.

## 기존 동작의 관찰 한계

- 현행 adapter는 hardErrors·필수 section·editorial 안전 기준으로 새 edition 채택 여부를 판단하며 qualityIssues만으로 결제를 실패시키지 않는다.
- MBTI 미상 사례 B/N/P: 9장 30문단 7,213자, 6개 독립 재료 부족. 8,000–10,000자와 문단 부족은 qualityIssues이며 hardErrors는 0. 별도 기준 SHA 재현 결과와 evidence digest가 일치한다. 새 DB로 이 부족을 자동 채우지 않았다.
- L2는 기존 attraction/partner 재료 경로가 보존되며 현재 selector에 take(L2)가 없다. CH02와 일대일 대응하는 새 배정 규칙을 만들지 않는다.
- source 이용 편중·전체 고객의 의미 중복률·실제 고객의 연애/양육 성과는 측정하지 않았다.
