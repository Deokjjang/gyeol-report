# 의미·출처·적용 조건 독해 검토

이번 검토의 대상은 static 연구 재료 164건 전체다. 작성 후 핵심 뜻, 네 원래 역할에 대한 기여, 긍정/위험/팩폭/반전, 가상 장면, 조정 행동, 반례, 출처 범위와 교차 챕터 차이를 다시 읽었다. 고객 원고의 판매 품질 승인이나 실제 고객의 관계 성과 평가가 아니다.

## 실제 출처를 읽고 구분한 사례

- 식신: `deep:ten_god:shi_shen`의 계산 관계 정의, `deep:application:ten_god:shi_shen:love`의 현대 조건부 연구, 본인 ESFP의 `expressive_love_style`를 구분했다. 명리의 산출 뜻과 MBTI의 표현 통로가 비슷해도 인과나 새 등록 Fusion으로 만들지 않는다.
- 비견: 동류 관계의 정의와 통근·월령·과중첩 검토를 남겼다. `freedom_based_attachment`는 실제 본인 INTP의 별도 자료다. 대등한 합의는 실제 두 사람의 선택으로 확인해야 한다.
- 정재: 실제 관리 관계와 원국의 감당 조건을 확인할 후보로 두고, 공동 장부 밖의 가사·돌봄을 묻는 현대 응용과 구분했다. 성별 전통 비유를 배우자의 실제 성격으로 쓰지 않는다.
- 도화: `definition.review=source_checked`, native 계산 지원, 실제 `supplement:marker:DOHWA`가 서로 다른 상태라는 점을 남겼다. 원래 원국 조건과 실제 형성 근거 확인 없이 표현·호감·동의의 사실로 승격하지 않는다.
- 홍염: `definition.review=repository_only`, 외부 전거 미확인 상태를 읽고 신규 확장을 보류했다. native 계산 성공은 신규 의미 검증 완료가 아니다.
- 천을귀인: 도움을 받을 통로의 상징이며 도움을 주는 능력이나 실제 부유한 배우자가 아니다. 의미의 방향을 뒤집지 않았다.
- C073–C082 중 사용한 8개 보완 연구: 실제 양측 축·assignment·domain/context가 필요하다. `sourceStatus=specific_source_not_yet_bound`를 실제 근거가 연결된 상태로 표시하지 않았다.
- 16유형 parenting: 기존 32개 strength 행의 trait와 `plainKo/positiveUse`, 16개 risk의 trait와 `risk`를 대조했다. 원래 장점·위험 문장은 보존하고 adult owner를 유지했다. child 63개 자료는 실제 고객의 자녀 자료로 전이하지 않았다.

## 문장과 내용 보완

- 명리 정의에서 정관의 극 방향을 `일간을 극하며 다른 음양`으로 명료하게 적었다. 계산식은 건드리지 않았다.
- 단순 사용 금지와 반례를 구분했다. 164건 모두 실제 적용이 달라지거나 보류되는 조건을 별도의 `counterexample`으로 작성했다. 금지·적용 한계는 `applicationLimit`과 `disallowed`에 따로 남겼다.
- 짧았던 부모 의견 허용·규칙 안내의 긍정 설명 두 곳을 구체화했다. 검사 기준을 낮춰 통과시키지 않았다.
- 12개 갈등·회복 묶음에 의도, 가능 행동, 상대의 가능한 해석, 커지는 조건, 반복 부담, 첫 확인 질문, 조정 행동과 회복이 통하지 않는 조건을 구분했다. 상대의 해석은 실제 알려진 사실이 아니다.

## 미검증·범위 한계

- 각 유형의 모든 후보가 모든 문단에 존재하는 DB는 아니다. 후보의 적용은 실제 본인 source와 문장 역할의 개별 검토가 필요하다. 네 역할의 구조 연구 완료가 고객 문장 승인 완료를 뜻하지 않는다.
- 원천의 경험과학적 예측력은 검증하지 않았고 주장하지 않는다. 과거 문헌의 모든 URL을 이번에 다시 열지 않았다.
- source 사용 편중과 고객 전체의 의미 중복률을 측정하지 않았다. 정확한 문자열이 다른 것은 의미 중복률이 낮다는 증거가 아니다.
- MBTI 미상 B/N/P는 기존 실제 원고가 9장 30문단 7,213자와 6개 재료 부족 진단을 보인다. 동일 기준 SHA에서도 evidence digest가 같았다. 신규 연구를 fallback으로 연결하거나 기존 원고를 채우지 않았다.
- 실제 고객 UI·Production·결제·인증·운영 DB·기존 구매자의 데이터는 이번 검토 대상으로 실행하지 않았다. 기존 저장본 재열람은 로컬 fixture 회귀 범위에서 확인했다.
